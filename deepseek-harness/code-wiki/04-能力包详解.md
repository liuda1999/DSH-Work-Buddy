# 04 能力包详解（Capability Seams）

> 每个能力族按"Service Definition → Providers → Consumers（模型可见工具）"组织。除特殊说明外，Service Definition 包声明 ctx 键与 `*/` 事件，Provider 包实现接口，`tool-*` 包把能力暴露为模型可见工具。

## 总表

| 能力 | ctx 键 | Service Definition | Providers | 模型可见工具 |
|---|---|---|---|---|
| 文件系统 | `ctx.fs` | `fs/fs` | `fs-local`、`fs-sandbox`、`fs-e2b` | `tool-fs`（read/edit）、`tool-fs-search`、`tool-str-replace-editor` |
| Shell 执行 | `ctx.shell` | `shell/shell` | `bash-local`、`pwsh-local`、`bash-sandbox`、`pwsh-sandbox` | `tool-bash`、`tool-pwsh`、`tool-bash-persistent` |
| 子进程 | `ctx.subprocess` | `subprocess/subprocess` | `subprocess-local`、`subprocess-e2b` | （被 shell/lsp/mcp 复用） |
| 持久终端 | `ctx.terminals` | `terminal/terminal` | `terminal-bash` | `tool-terminal` |
| LSP | `ctx.lsp` | `lsp/lsp` | `lsp-stdio` | `tool-lsp`（`lsp` 工具） |
| Web | `ctx.web` | `web/web` | `web-fetch-http`、`web-search-deepseek/exa/perplexity` | `tool-web`（搜索/抓取） |
| 技能 | `ctx.skills` | `skill/skill` | `skill-filesystem` | `tool-skill`（目录/加载） |
| MCP | —（经 `ctx.tools`） | — | `mcp/mcp-client` | MCP server 工具直接进注册表 |
| 沙箱 | `ctx.sandbox` | `sandbox/sandbox` | `sandbox-local`、`sandbox-windows-acl`、native Landlock | （消费者包装 argv） |
| 代码执行 | `ctx.codeRuntime` | `code-runtime/code-runtime` | `code-runtime-worker-thread` | `run_code`（Code Mode，在 dsh-tools 内） |
| 子代理 | `ctx.subagents` | `subagent/subagent` | 7 种（见下） | `tool-subagent`、`tool-subagent-control`、`tool-subagent-report` |
| 后台任务 | `ctx.jobs` | `jobs/jobs` | `jobs-local` | `tool-jobs`（`job_*`） |
| 工作流 | `ctx.workflowEngine` | `workflow/workflow` | `workflow-worker-thread` | `tool-workflow`、`tool-ralph` |

## 1. fs — 文件系统能力

### `dsh-fs`（Service Definition，`packages/fs/fs/src/index.ts`）

- 定义 `ctx.fs` 与 `FileSystem` 抽象：`resolve`（路径 → 目标身份）、`readText` / `readBytes`、`writeText` / `editText`（原子写入契约）、stat/stream/window/observation 词汇。
- 事件：`fs/write-intent`、`fs/edit-intent`（写前意图，策略可挂）、`fs/observed`（观察通知）。
- 目标身份基于 realpath；跨边界 id 用 branded 类型。

### `dsh-fs-local`（本地 Provider）

`LocalFileSystem`（`src/index.ts`）：`resolve`、`readText`、`readBytes`、`writeText`、`editText` 等，是宿主文件系统实现。

### `dsh-fs-sandbox` / `dsh-fs-observation-policy`

- 前者组合 `fs-local` + `sandbox` + `sandbox-policy`，把本地 FS 限制进沙箱世界。
- 后者监听 `fs/*` 事件实施观察策略。

### `dsh-tool-fs`（Consumer，模型可见）

| 工具 | 关键参数 | 行为 |
|---|---|---|
| `read` | `file_path` / `offset` / `limit` | UTF-8 读取，带 stat、流式、窗口、行号内容输出（`src/read.ts`） |
| `edit` | `file_path` / `old_string` / `new_string` / `replace_all` | 字面量替换编辑，经 `ctx.fs.resolve` + `ctx.fs.editText`，记录 observation（`src/edit.ts`）；结果以 contextual diff 呈现（`src/diff.ts`） |

### `dsh-tool-fs-search`、`dsh-tool-str-replace-editor`

- 前者：bash 驱动的发现型工具（grep/glob 类），结合 `spill`（超大结果外溢）与 `output-retention`。
- 后者：字符串替换编辑器工具的独立变体。

## 2. shell — Shell 执行能力

### `dsh-shell`（Service Definition，`packages/shell/shell`）

- `ctx.shell`：request/spec 分离的执行缝——`resolve(request): Spec` 是拥有者实现中的**显式默认化步骤**（仓库存范），`run()` 内不做隐藏默认。依赖 `sandbox`、`settings`、`subprocess`。

### Providers

- `bash-local` / `pwsh-local`：本地 bash / PowerShell 实现（经 `ctx.subprocess` 派生，读 settings，带 timeout）。
- `bash-sandbox` / `pwsh-sandbox`：组合 local 实现 + `sandbox` + `sandbox-policy`，命令在限制世界执行。
- `shell-env`：shell 环境注入（依赖 home-paths 与 session-persistence）。

### Consumers

`tool-bash` / `tool-pwsh`（一次性命令工具，含审批 `user-approval`、job 集成、`shell-env`）、`tool-bash-persistent`（复用持久 PTY 终端）。

## 3. subprocess — 子进程能力

- `dsh-subprocess`（Service Definition）：`ctx.subprocess`，进程派生/进程树管理抽象。
- `dsh-subprocess-local`：本地实现（跨平台进程树跟踪；pnpm `allowBuilds` 注释提到 macOS spawn helper 的 exec 位修复 postinstall）。
- `dsh-subprocess-e2b`：E2B 云端实现。
- 被能力：shell、lsp-stdio、mcp-client、hooks、subagent（外部进程类）复用。

## 4. terminal — 持久 PTY 能力

- `dsh-terminal`（Service Definition）：`ctx.terminals`，owner 作用域的持久终端会话。
- `terminal-bash`：bash 后端（组合 sandbox/sandbox-policy/subprocess）。
- `tool-terminal`：`terminal` 模型工具（PTY 交互，job 集成，output-retention）。

## 5. lsp — 语言服务器能力

- `dsh-lsp`（Service Definition）：`ctx.lsp`，语言服务器抽象。
- `lsp-stdio`：通用 stdio 传输 provider（依赖 fs/subprocess/timeout）。
- `tool-lsp`：`lsp` 模型工具（诊断、定义跳转等；工具呈现意图 `locations`）。

## 6. web — Web 能力

- `dsh-web`（Service Definition）：`ctx.web`，搜索与抓取双缝。
- Providers：`web-fetch-http`（HTTP 抓取）、`web-search-deepseek`（DeepSeek 搜索，组合 agent/credentials/settings）、`web-search-exa`、`web-search-perplexity`。
- `tool-web`：搜索/抓取模型工具；结果视图 `WebSearchResultView` / `WebFetchResultView`。

## 7. skill — 技能能力

- `dsh-skill`（Service Definition）：skill provider 注册表（依赖 llm/scope 词汇）。
- `skill-filesystem`：从文件系统（含 home-paths）发现技能的本地 provider。
- `skill-badge`：技能徽章（skill 呈现辅助）。
- `tool-skill`：技能目录/加载模型工具。

## 8. mcp — Model Context Protocol

- `mcp-client`：连接外部 MCP server（stdio 传输经 subprocess），把 MCP 工具直接注册进 `ctx.tools`；支持 attachment。配置经 cordis.yml 声明 MCP server，`verify-cordis-config` 强制裸插件出现在解析器 manifest 的 `dependencies`。

## 9. sandbox — 进程限制

- `dsh-sandbox`（Service Definition）：`ctx.sandbox`，进程限制缝；消费者在 spawn 前包装 argv。
- `sandbox-local`：本机后端（Linux bwrap/Landlock、macOS Seatbelt 分发；Landlock 经 `native/landlock-run` addon）。
- `sandbox-policy`：策略层（决定哪些命令受限，喂给 system-prompt 提示模型）。
- `sandbox-windows-acl`：Windows ACL 后端。
- native：`@deepseek-ai/node-addon-landlock-run`（见 [08-Python-Native-工具链](08-Python-Native-工具链.md#2-native-landlock-沙箱)）——自限制后 exec，提供 `launcherPath/probe/grantArgs` API。

## 10. e2b — E2B 云沙箱（POC）

`e2b/e2b`（客户端）+ `fs-e2b` + `subprocess-e2b`：把 fs 与 subprocess 指向 E2B 沙箱——演示"换 provider 迁移整个执行世界"（Bash/PTY/LSP 随行）。

## 11. code-runtime — 代码执行（Code Mode）

- `dsh-code-runtime`（Service Definition）：`ctx.codeRuntime`（`language: 'typescript' | 'python'`）。
- `code-runtime-worker-thread`：worker 线程 provider。
- Consumer 是 `dsh-tools` 内建的 `run_code`：非原生工具模式下模型只能直接调 `run_code`，其余工具在程序内经 SDK 调用（`tools/code-dispatch-log` 事件替换日志副本）。

## 12. subagent — 子代理委派

- `dsh-subagent`（Service Definition）：provider 注册表契约 + 委派 Consumer 依赖面（组合 agent-presets、jobs、sandbox、session-projection-cache、user-approval 等）。
- Providers（7 种）：

| Provider | 方式 |
|---|---|
| `subagent-fork-in-process` | fork 当前会话日志前缀，进程内新建子 agent |
| `subagent-spawn-in-process` | 进程内全新子 agent |
| `subagent-in-process-driver` | 上述两者的进程内驱动基建 |
| `subagent-acp` | 外部 ACP 进程 |
| `subagent-claude-code` | 外部 Claude Code 进程 |
| `subagent-codex` | 外部 Codex 进程（经 sdk-protocol） |
| `subagent-dsh-sdk` | 经 TS SDK 的另一个 dsh 实例 |

- Consumers：`tool-subagent`（委派工具）、`tool-subagent-control`（控制）、`tool-subagent-report`（汇报）。

## 13. jobs — 后台任务

- `dsh-jobs`（Service Definition）：`ctx.jobs`，通用后台任务运行时；`jobs-local` 本地实现。
- `tool-jobs`：`job_*` 工具（启动/收集/停止后台工作；output-retention 限制输出）。

## 14. workflow — 工作流

- `dsh-workflow`（Service Definition）：`ctx.workflowEngine`（`WorkflowEngine`）。
- `workflow-worker-thread`：worker 线程引擎 provider。
- `tool-workflow`（`workflow` 工具）与 `tool-ralph`（"Ralph" 循环式自主工作流工具，组合 subagent）。

## 15. 任务与协作类能力（简述）

| 包组 | 职责 |
|---|---|
| `goal/` | 同会话目标持久化与生命周期：`goal`（Service Definition，`ctx.goals`）、`command-goal`、`goal-round-driver`（目标轮驱动）、`tool-goal` |
| `plan/plan-mode` | Plan 模式：以记录状态实现的计划协作（直接入口命令 + 审阅退出），依赖 user-questions |
| `todo/tool-todo` | 模型可见 `todo_write` 工具 |
| `schedule/schedule` | 会话内定时后续（cron 式） |
| `compaction/` | 上下文压缩：`compaction`（Service Definition + 命令）、`compaction-basic`（基础 provider）、`compaction-tool-result-pruner`（工具结果裁剪）、`command-compact` |
| `context/` | 模型可见请求上下文：`agent-instructions`（AGENTS.md 类指令注入）、`time-context`（时间）、`tmux-context`（tmux 环境）、`session-reference`（引用其他会话） |
| `spill/` | 超大结果外溢：`spill`（Service Definition）、`spill-local`、`spill-policy`（工具结果外溢策略，监听 tools 管线） |
| `feedback/` | 人类反馈：`message-feedback`（消息级反馈持久化）、`command-feedback`（/feedback 命令，组合遥测） |
| `guard/` | 循环卫生：`repeat-tool-reminder`（重复调用提醒）、`tool-call-timeout-policy`（`tools/execute` 截止执行器） |
| `hooks/` | Claude Code / Codex 钩子桥：`hook-protocol`（wire 协议库）、`hooks-claude-code`、`hooks-codex`（把外部 agent 的 hook 事件桥进本会话） |
| `extensions/` | 运行时自改（self-modification）：`cordis-host-runner` / `cordis-client-runner`（活插件/服务检查）、`tool-cordis`（模型可挂/卸插件的工具）、`client-ui-cordis`（对应 UI）。仓库 demo `demo:cordis` 演示 agent 检查并修改自己的运行时插件树 |
