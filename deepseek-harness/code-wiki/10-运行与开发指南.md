# 10 运行与开发指南

> 依据 `README.md`、`docs/development.md`、根 `package.json` scripts、`AGENTS.md`。

## 1. 前置条件

- **Node.js**：`^22.19.0 || >=24.0.0`（CI 覆盖 22.19 / 24 / 26）。
- **pnpm**：仓库钉住 `pnpm@11.7.0`（`packageManager` 字段），经 Corepack 启用：`corepack enable`。
- **Git** ≥ 2.26（worktree 级配置扩展）。
- 可选：`DEEPSEEK_API_KEY`（Web/headless/ACP demo 与真 API e2e 需要）。

## 2. 作为用户运行

```sh
# npm 直接运行 Web UI（默认 http://127.0.0.1:3080）
npx @deepseek-ai/dsh web
```

## 3. 从源码构建与运行

```sh
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install          # 同时安装 lefthook worktree 钩子与翻译配对 merge driver
pnpm run typecheck    # 首次克隆后跑一次；成功即环境就绪
pnpm run build
pnpm dsh web
```

构建流水线（根 scripts 实际执行的顺序）：

```text
tsc -b tsconfig.host.json        # Host 聚合 tsc（产出 lib/types 声明+JS）
tsdown --env.DSH_BUILD_FACE host # Host 打包；Typert 在此阶段生成类型反射产物
tsc -b tsconfig.client.json      # Client 聚合 tsc
tsdown --env.DSH_BUILD_FACE client
vite build (apps/web)            # Web 前端
```

注意：`typecheck`/`lint`/`doc-typecheck` 都会先跑完 Host lib 阶段（含 Typert 契约生成）再做 Client 检查；`pnpm run build` 才有 bundled JS 与声明——fresh worktree 上 publint 类门禁需先 build。

## 4. 环境变量与密钥

```sh
DEEPSEEK_API_KEY=sk-...           # 必需（真 API 场景）
DEEPSEEK_BASE_URL=https://...     # 可选，默认公共 API
```

- 也可放在仓库根 gitignored 的 `.env`。
- 永不提交凭据；无 key 时 e2e 自动跳过。
- cordis.yml 的插件 `config` 与 entry `disabled` 允许 `!!js` 表达式（绝不用 `!js`），其余元数据保持字面量。

## 5. dsh CLI 常用命令

```sh
pnpm dsh web                                # Web UI（= --profile web）
pnpm dsh --profile headless "task"          # 一次性 headless agent（需 key）
pnpm dsh --profile web --dump-config        # 打印实际启动的插件配置树（不启动）
pnpm dsh --profile web --dump-default-config
pnpm dsh plugin --profile web add <pkg>     # 安装第三方 bundle（pnpm 后台）并入栈
pnpm dsh plugin --profile web remove <pkg>
```

## 6. Demo（需先 `pnpm run build` + key）

```sh
pnpm dsh --profile headless "summarize this workspace"
pnpm run demo:cordis     # agent 检查并修改自己的运行时插件树（自改演示）
pnpm run demo:acp        # ACP 自动化服务器（JSON-RPC stdio）
pnpm run demo:code-mode  # Code Mode 演示
pnpm run mock:llm        # 本地 LLM mock 服务器（测试用）
pnpm run dev:web         # web 开发模式（--poll）
```

## 7. 测试命令

| 命令 | 用途 |
|---|---|
| `pnpm run test` | Vitest 单元测试 |
| `pnpm run test:coverage` | **CI 覆盖门禁**（`packages/*/*/src` 每文件 100%） |
| `pnpm run test:e2e` | 真 API e2e（需 key，无 key 自跳过） |
| `pnpm run test:snapshot` | keyless 快照回放（`-t <name>` 过滤） |
| `pnpm run test:snapshot:record` | 重录预期输出（需 key） |
| `pnpm run test:web` / `test:web:refresh` | 构建后浏览器测试 |
| `pnpm run test:web:perf` / `test:web:stress` | 性能 / 压力 |
| `pnpm run test:gui` | client + host 包测试 |

本地检查原则：**选择覆盖变更面的最小检查**（行为→聚焦测试；模型/用户输出→快照；文档→doc-sync；发布路径→build/hygiene；供应商行为→e2e）；不默认全量重跑。

## 8. Lint / 文档 / 卫生门禁

```sh
pnpm run lint            # oxlint（先完成 Host lib 阶段）
pnpm run lint:fix
pnpm run duplication     # jscpd 跨文件克隆检测
pnpm run knip            # 未用导出检测
pnpm run publint         # 包入口与产物校验（需 build）
pnpm run hygiene         # rescope-vendor + knip + publint + constraints + 一系列 verify-*
pnpm run doc-sync        # 全部文档门禁（verify-md-links/wrap、doc-typecheck、type-equiv、budgets、catalogs --check 等）
pnpm run docs:dev / docs:build   # VitePress 文档站
pnpm run check:all       # 本地全量门禁（可选，独立于 git hooks）
```

Git hooks（lefthook，安装于 `pnpm install`）：pre-commit 做暂存区校验（pairing 记录、staged oxlint、THIRD_PARTY_NOTICES 再生成、空白检查、vendor manifest 守卫）；pre-push 跑 `pnpm run typecheck`。hooks 有意不跑测试/快照/构建。

## 9. 仓库约定精选（改代码前必读）

- **注册即效果**：一切贡献经 `ctx.effect()` / `ctx.on()`；`register()` 返回 disposer。
- **插件导出形态**：服务包默认导出 Service 类；函数插件具名导出 `name` / `inject` / `Config` / `apply` 且无默认导出（混用会丢命名空间）。
- **可选服务用 `ctx.get(name)`**；`ctx.<name>` 留给声明注入。
- **waterfall 监听器必须调 `next()`**。
- **类型化事件用声明合并**；事件 JSDoc 需 `@mode` 与载荷 `@param`；closed union 以 `assertNever` 收尾。
- **branded id**：跨边界不透明 id 用 `Branded<B>`（`dsh-brand`），不用裸 `string`。
- **类型安全边界**：同进程类型化边界信任 TS，不加运行时校验；校验只发生在 parser/config、队列、模型/工具 JSON、持久化、worker、进程、wire 边界。
- **源码面 vs 产物面不混用**；新包在且仅在一个聚合（Host 或 Client）注册。
- **文件恰好一个尾随换行**；TODO 标记按紧急度用 `FIXME`/`TODO`/`XXX`。
- 非平凡变更必须同 PR 附 Agent Note；文档与代码同改（README/JSDoc 契约）。
- 完整约定见根 `AGENTS.md`（`CLAUDE.md` 是其符号链接）；包级规则见 `packages/AGENTS.md`；文档标准见 `docs/AGENTS.md`。

## 11. 故障排查速查

| 症状 | 处置 |
|---|---|
| `pnpm --version` 不对 | `corepack enable` |
| lefthook/merge driver 缺失（缓存恢复导致） | `node scripts/install-lefthook.mjs` |
| typecheck 报 Context 键冲突 | 检查新包是否被同时注册进两个聚合；或误在 Host 侧 import 了 Client 包 |
| 快照失败 | `pnpm run test:snapshot:record` 重录（需 key）；先确认行为变更是否合理 |
| Windows 专项诊断 | `pnpm run check:windows-wine`（需 wine；平时勿跑，CI 拥有该信号） |
