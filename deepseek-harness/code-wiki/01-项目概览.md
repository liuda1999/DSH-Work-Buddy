# 01 项目概览

## 1. 项目定位

DeepSeek Harness（命令名 `dsh`）是 [DeepSeek AI](https://deepseek.com) 开源的 **Agent Harness**——为 LLM 编码/办公代理提供运行框架：

- **架构核心思想**："everything is a plugin"。模型适配器、工具注册表、会话日志、甚至 Agent 循环本身，都是挂载到共享 Cordis Context 上的插件；没有需要打补丁的特权核心，任何部分都可从配置替换或扩展。
- **底层框架**：[Cordis](https://github.com/cordiverse/cordis)（本仓库以 vendored 源码形式钉住版本并 rescope 为 `@deepseek-ai/*`，见 [07-vendor-Cordis框架](07-vendor-Cordis框架.md)）。Cordis 的设计论文为《A Programming Paradigm for Spatiotemporal Composability》。
- **产品形态**：
  - `dsh web`：浏览器 Web UI（React SPA + Node 宿主，默认 `http://127.0.0.1:3080`）
  - `dsh --profile headless`：无服务器一次性任务运行器
  - ACP（Agent Client Protocol）自动化服务器（JSON-RPC over stdio）
  - TypeScript / Python 双 SDK（进程外驱动同一运行时）
- **状态**：developer preview，快速迭代期，承诺会有破坏性变更。许可证 MIT。

## 2. 设计理念速览

| 理念 | 含义 |
|---|---|
| 一切皆插件 | 所有产品能力经 `ctx.effect()` / `ctx.on()` 注册，插件卸载时注册自动回滚（"registrations are effects"） |
| 模型可见 ⟺ 已记录 | 任何进入模型请求的输入必须能从 Session 日志重建；新增模型可见输入必须新增 Session 事件 |
| 能力缝三角色 | 一个能力 (capability) = Service Definition（接口声明）+ Service Provider（实现）+ Consumer（使用，通常是模型可见工具），三者齐备才构成完整缝 |
| 插件而非改循环 | 新行为挂在文档化的扩展点上；修改 `agent-loop` 本身必须更新 `docs/architecture.md` |
| 显式优于隐式 | 包边界处的默认值是显式的 `resolve(request): Spec` 步骤，而非 `run()` 内的隐藏 `?? default` |
| 配置可调 | 部署可变的参数是经校验的 `Config` 字段（cordis.yml 可改），禁止插件内硬编码可调参数 |
| 失败要响 | 自包含的错误在加载期就报错，否则在最早可解析点报错；绝不静默跳过缺失引用 |

## 3. 仓库顶层布局

```
deepseek-harness-master/
├── apps/                  # 产品组装层
│   ├── cli/               #   `dsh` CLI（bin 入口、profile 启动、插件管理、配置导出）
│   └── web/               #   Web 前端（Vite 构建，产物由 dsh web 托管）
├── docs/                  # 架构文档、子系统参考、cookbook、术语表（中英双语）
├── examples/              # 可运行的 cordis.yml 示例（acp-agent、mcp-memory、web-cordis、web-schedule）
├── native/                # @deepseek-ai/node-addon-landlock-run（Linux Landlock 沙箱启动器源码）
├── packages/              # ~45 个分组、150+ 个 @deepseek-ai/dsh-* 工作区包（主体代码）
├── python/                # Python SDK（deepseek-harness-sdk）+ 打包运行时（sdk-runtime）
├── scripts/               # 仓库门禁（gate）与生成器（module graph、catalogs、release）
├── vendor/                # vendored Cordis 框架及配套库（钉住上游 SHA，rescope 为 @deepseek-ai/*）
├── website/               # VitePress 文档站（投影 docs/ 的部分双语页面）
├── .agents/               # Agent 工作流、Skills、Agent Notes（决策记录）
└── .github/workflows/     # CI：ci / e2e / release / sandbox / e2b-e2e
```

`packages/<group>/<pkg>/` 的分组即模块边界（每组有独立 README 维护包与 `ctx` 键映射），主要分组：

| 组 | 角色 | 代表包 |
|---|---|---|
| `core/` | 产品 API 脊柱：会话、提示词、工具、Agent 服务与具体循环 | session、agent、agent-loop、tools、system-prompt、scope |
| `llm/` | LLM 能力：抽象服务 + 供应商适配器 | llm、llm-deepseek、llm-pi-ai、llm-retry、token-meter |
| `api/` + `typert/` | 远程 BFF 组装、Typert 类型图 RPC 网关 | api-gateway、api-remotes；typert-generator/loader/protocol/registry |
| `fs/` `shell/` `subprocess/` `terminal/` `lsp/` `web/` `skill/` `mcp/` | 模型可见能力缝（文件/命令/进程/PTY/LSP/网络/技能/MCP） | 见 [04-能力包详解](04-能力包详解.md) |
| `sandbox/` `e2b/` | 进程限制缝（bwrap/Landlock/Seatbelt/Windows ACL）与 E2B 云沙箱 | sandbox-local、sandbox-policy；e2b、fs-e2b |
| `subagent/` `jobs/` `workflow/` `goal/` `plan/` `todo/` `schedule/` | 委派与任务编排能力 | subagent（7 种 provider）、workflow-worker-thread |
| `compaction/` `context/` `spill/` `feedback/` | 上下文管理与反馈 | compaction-basic、time-context、spill-policy |
| `session/` `session-query/` `storage/` `settings/` `credentials/` `identity/` `attachment/` `workspace/` | 持久化与数据平面 | session-persistence-jsonl/sqlite、storage-sqlite |
| `interaction/` `guard/` `hooks/` `extensions/` | 人机协作、循环卫生、Claude Code/Codex 钩子桥、运行时自改 | user-approval、commands；tool-cordis |
| `host/` `client/` `boot/` `bundle/` `preset/` `acp/` `sdk/` | Web 宿主/浏览器 halves、启动 glue、Profile 组合层 | host-webserver；client-web + ui-* 插件 |
| `examples/` `test-support/` `util/` `runtime-diagnostics/` | 示例、测试基建、零依赖工具、运行时不变量 | agent-loop-testkit、llm-mock-server；brand、timeout、invariants |

## 4. 技术栈

| 层 | 技术 |
|---|---|
| 语言 | TypeScript 6（`strict: true` + `noImplicitAny`），全仓 ESM（`"type": "module"`），相对导入用 `.ts` 后缀 |
| 运行时 | Node.js `^22.19.0 \|\| >=24.0.0`（CI 覆盖 22.19 / 24 / 26） |
| 包管理 | pnpm 11.7.0 workspace（Corepack），`pnpm-workspace.yaml` 定义 `vendor/*`、`packages/*/*`、`apps/*`、`website` 等 |
| 框架 | vendored Cordis（rescope `@deepseek-ai/cordis`，是每个 harness 包的 peerDependency） |
| 构建 | `tsc -b`（Project References，Host/Client 双聚合）+ tsdown 打包运行时；Typert 在 Host tsdown 阶段生成类型反射产物 |
| 前端 | React 18 + Vite 6，浏览器端插件树由 host 推送（client/web 内核） |
| 测试 | Vitest（unit / coverage / e2e / snapshot / web browser / perf / stress 多配置）+ Playwright |
| Lint/门禁 | oxlint、jscpd（重复代码）、knip、publint、lefthook（git hooks）、自研 verify-* / gen-* 脚本群 |
| Python | `deepseek-harness-sdk`（uv/pyproject，内置钉住的 Node 运行时二进制） |
| Native | C++ Node addon（node-gyp/prebuild，Landlock 自限制 exec） |

## 5. 规模与质量设施

- 150+ 工作区包，全部命名 `@deepseek-ai/dsh-<name>`；vendored 包 `@deepseek-ai/<原名>` 且 `private: true`。
- 每个包必须有 `./invariant`（运行时不变量断言）与 `## Known Limitations and Deferred Work` README 节（或进入豁免名单）。
- 文档与代码同步由机器门禁强制：`verify-md-links`、`verify-type-equiv`（文档中粘贴的类型必须与源码逐字一致）、`verify-doc-budgets`（字数预算）、`doc-typecheck`（文档内 ts 代码块必须可编译）等 40+ 个 verify/gen 脚本。
- 非平凡变更必须在同一 PR 附带 Agent Note（`.agents/notes/` 决策记录体系）。
