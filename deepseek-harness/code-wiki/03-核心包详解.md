# 03 核心包详解（core/ + llm/）

> 核心脊柱六包 + LLM 能力族。所有路径相对仓库根；`ctx` 键即 Cordis 声明合并到 `Context` 上的服务属性。

| 包 | ctx 键 | 一句话职责 |
|---|---|---|
| `packages/core/session` → `dsh-session` | `ctx.sessions` | 事件溯源会话：只追加日志、内存 store、派生 LLM 消息历史 |
| `packages/core/scope` → `dsh-scope` | （库，无键） | per-agent 作用域注册与事件路由原语 |
| `packages/core/agent` → `dsh-agent` | `ctx.agents` / `ctx.agent` | Agent 接口、活注册表、工厂委派、进程内 initiator 作用域 |
| `packages/core/agent-loop` → `dsh-agent-loop` | `ctx.agentLoop` | 默认驱动器（`ReactLoopAgent`），实现 Agent 接口并发布到注册表 |
| `packages/core/tools` → `dsh-tools` | `ctx.tools` | 作用域工具注册表 + 受保护的执行管线 |
| `packages/core/system-prompt` → `dsh-system-prompt` | `ctx.systemPrompt` | 有序 prompt 区段、动态上下文、工具 schema、提示词变量 |
| `packages/llm/llm` → `dsh-llm` | `ctx.llm` | 消息/流词汇表 + 适配器缝（waterfall 可拦截的流式调用 API） |

辅助：`core/agent-default-model`（按 settings 解析默认模型）、`core/agent-tool-presentation`（工具调用的 UI 呈现意图契约）。

---

## 1. dsh-session（`packages/core/session/src/`）

**事件溯源会话服务**。持久化是插件关注点：订阅 `session/event`，在 `session/flush` 时排水落盘。

### 关键类型与方法

| 符号 | 说明 |
|---|---|
| `SessionStore`（默认导出 Service） | `ctx.sessions`。会话的进入/发布/派生 API（含 `fork(source, boundary?, childSessionId?)`） |
| `Session` | 单个活会话；`SessionId` 为 branded id |
| `SessionEvent` / `SessionEventMap` | 持久事件判别联合与类型化映射（`SessionEventType` 枚举已知类型 `KNOWN_SESSION_EVENT_TYPES`） |
| `SESSION_FORMAT_VERSION` | 格式版本常量（当前 `0`，无兼容承诺） |
| `deriveMessages()` | 从日志投影模型历史（`deriveEventMessage`、`SurfaceManager`/`foldSurface` 实现表面折叠） |
| `SessionPreparation` | 校验/快照创建头部的准备边界（`CreateSessionOptions` / `PrepareSessionOptions`） |
| `validateSessionHeader()` | 校验并冻结创建头（version/id/createdAt/cwd 绝对路径/parentSession） |
| `decodeStorageRecord` / `packChunkRuns` | 持久化层的记录编码与 chunk 行打包（`ChunkRow` / `StorageRecord`） |
| `interruptedTurnClosers`, `TOOL_NOT_STARTED`, `TOOL_OUTCOME_UNKNOWN` | 中断 turn 的修复词汇（`repair.ts`） |

### 贡献事件（全部 scope 过滤分发）

| 事件 | 模式 | 语义 |
|---|---|---|
| `session/created` | emit | 发布期创建通告；同步抛出可否决并回滚（配对 dispose） |
| `session/disposed` | emit | 会话离开 store（含发布回滚） |
| `session/event` | emit | 提交后 fire-and-forget 追加流（观察者失败仅记录） |
| `session/flush` | parallel | 可等待的持久化检查点，调用方 await 全部监听器 |

另向 `dsh-typert-protocol` 注册 `session: TypertLookup<Session, SessionId>`（Remote RPC 可调用）。

## 2. dsh-scope（`packages/core/scope/src/index.ts`）

作用域原语库（无 ctx 键）。为 agent/session/tool 的 scoped 注册与事件路由提供底层机制：

- `createScope` / `scopeOf` / `scopeTarget` — 建立/查询作用域层（`ScopeKey` / `ScopeLayer` / `Scoped<T>`）。
- `AnonymousEntries` / `NamedEntries` / `ScopedLayers` — 作用域条目容器（tools 与 system-prompt 的注册表都基于它们）。
- 核心效果：在 `agent.ctx` 上注册的贡献只对该 agent 可见并随其卸载回滚；`session/created`、`tools/*` 等事件的 agent-scoped 监听器只收到经该 agent 上下文进入的事件。

## 3. dsh-agent（`packages/core/agent/src/`）

**Agent 服务**：活注册表、工厂委派、进程局部 initiator 作用域。具体创建与驱动属于 loop。

### AgentRegistry（`ctx.agents`）

| 方法 | 说明 |
|---|---|
| `create(options: CreateAgentOptions)` | 程序化创建：调用者给唯一 `sessionId` + 元数据（`cwd`/`parentSession`/`seedLength`/`origin`/`delegationDepth`/`agentPreset`）、可选 `seed`（fork 前缀，必须 seq 0 起连续、无损 JSON、无开放 turn/step）、`agentOptions`、`signal`、`setup` |
| `resume(options: ResumeAgentOptions)` | 在已持久会话上重建 agent（先加载持久化，再 mint `agentCtx` 并 await setup，之后才发布） |
| `withInitiator()` | initiator 拥有的私有链：在每个编排入口恢复 Agent，派生 `agent.session`，向下闭包传递（禁止把叶子助手参数从 `Session` 放宽为 `Context`） |

`setup` 契约：**只组合、绝不驱动**——在 session/agent 发布前于 `agentCtx` 上注册 scoped 工具、prompt 区段/变量、`restrict()`、监听器、await 子插件；可返回 `AgentSetupCommit`（发布边界处的同步重校验）。setup 抛出/commit 抛出/宿主卸载 ⇒ 整体回滚，两个 id 都不发布。

### Agent 接口（`runtime-types.ts`，`ctx.agent` 为当前关联）

```ts
interface Agent {
  readonly id: SessionId          // 与 session 共享的唯一身份
  readonly options: AgentOptions  // provider / model / maxTokens
  readonly session: Session       // 活会话；其日志是持久真源
  readonly inbox: Inbox           // 持久待办工作的 agent 投影
  readonly status: AgentStatus    // 'idle' | 'running'（每次转换发 agent/status）
  readonly ctx: Context           // agent 作用域上下文；贡献 agent 局部、随 dispose 回滚
  cancel(cause: AgentCancelCause, options?: CancelOptions): void  // keepInbox 保留排队工作
  whenIdle(): Promise<void>       // 整 agent 活动静止
  runMaintenance<T>(task): Promise<T>  // 真 idle 段内跑非 turn 维护任务
  send(message, target: InboxTarget, wakeup: boolean): void       // 底层路由
  followup(message: UserMessage): void  // 排队新 turn 并唤醒（该 turn 的唯一普通消息）
  steer(message: UserMessage): void     // 最近 step 的转向；idle 则开新 turn
  inject(message: UserMessage): void    // 排队模型可见上下文，不唤醒
}
```

### agent/* 事件（活扩展点；持久事实仍是 session 事件）

`agent/created`、`agent/disposed`、`agent/status`、`agent/inbox/inserted`、`agent/inbox/claimed`（被拒 step 的消息在此终结：既不丢弃也不作为 user/message 重发）、`agent/pre-step`（waterfall：`reject | enter(messages)`）、`agent/request`（waterfall）、`agent/turn-stopping`（serial、无 next）、以及验证/续跑类事件。分发工具：`agentCarrier` / `agentEvents` / `emitAgentEvent` / `assembleContextFor`（`dispatch.ts`）。

## 4. dsh-agent-loop（`packages/core/agent-loop/src/`）

**具体循环插件**：创建 scoped `ReactLoopAgent`，经 agent/session 注册表发布，并拥有有序拆除。

| 符号 | 说明 |
|---|---|
| `AgentLoop`（默认 Service 导出） | `ctx.agentLoop`；工厂级所有权管理 |
| `ReactLoopAgent`（`agent.ts`） | 默认 Agent 接口实现，驱动 [02 中描述的 turn 流程](02-整体架构.md#4-turn-流程agent-循环核心时序) |
| `FactoryOwnership` | 工厂级拆除：活 agent teardown 集合 + 启动任务集合；`dispose()` 先 abort（"agent loop is not active"）再并行等待全部 |
| `raceAbort` / `raceAbortCall` | 创建期可取消操作的工具（signal 一到即抛，可释放取消后到达的值） |
| `DEFAULT_MAX_PARALLEL_TOOL_CALLS` | 并行工具调用上限常量（可被 Config 覆盖） |

循环读取每次 step 所需的 prompt 区段与工具 schema（来自注册），按 inbox 认领消息，经 `agent/request` → `llm/stream` 完成模型调用，再进工具管线；`tools` 还欠请求或 next-step 输入到达则继续下一个 step。

## 5. dsh-tools（`packages/core/tools/src/index.ts`）

**工具注册表 + 模型呈现模式 + 五段执行管线**（pre → guard/around → post → result）。

### ToolRuntime（`ctx.tools`）执行管线事件

| 事件 | 模式 | 语义 |
|---|---|---|
| `tools/pre-execute` | waterfall | 派发前 allow / deny / ask；缺失审批支持时 ask 落为拒绝；异步闸必须观察 `exec.signal` |
| `tools/execute` | waterfall | around-dispatch：超时、重试、指标；包装器只能改 `exec.signal`，调用身份不可变 |
| `tools/post-execute` | waterfall | 接受/替换/丰富/阻塞规范化结果；抛错的工具也到达此处 |
| `tools/code-dispatch-log` | waterfall | 仅 Code Mode：替换 `run_code` 子派发结果的**日志副本**（如 spill 策略的预览+定位器）；程序已拿到完整值，模型不可见 |
| `tools/result` | emit | 观察深冻结的最终结果（监听器失败被容纳） |
| `tools/change` | emit | 注册集/作用域限制变化（非 scope 过滤：全局通知） |

### 工具定义与校验（`schema.ts` / `json-schema.ts`）

- `defineTool(options: DefineToolOptions)` — 声明式工具定义（参数 schema → 类型推断 `InferArgs`）。
- `valueSchemaSpecToJsonSchema` / `parameterSchemaSpecToJsonSchema` / `validateArgs` / `ToolArgsError` — 规范转 JSON Schema 与参数校验。
- `assertSupportedJsonSchema` / `validateJsonSchemaValue` / `JsonSchemaError` — JSON Schema 白名单校验（边界处才校验）。

### 呈现意图（`presentation.ts`，UI 渲染契约）

工具经 `presentCall` / `presentResult` 声明渲染意图：`generic` / `terminal` / `diff` / `locations`（`ToolCallView`、`ToolResultView`、`DiffCallView`、`SearchResultView`、`WebFetchResultView` 等视图类型）。呈现方法是 `args` 的纯函数，属工具设计的一部分。

### Code Mode（`code-mode.ts`）

`RUN_CODE_NAME`（`run_code`）折叠：非原生模式下模型只能直接调 `run_code`，其余工具经 SDK 声明在程序内调用。`SDK_RENDERERS` 按 `ctx.codeRuntime.language` 渲染 `tools:sdk` 区段（typescript → `renderToolsSdk`，python → `renderToolsSdkPy`）；新增后端语言需三处并行修改（`CodeSdkLanguage` 成员、渲染表项、`RUN_CODE_FLAVORS` schema 项），漏一处即类型检查失败。

## 6. dsh-system-prompt（`packages/core/system-prompt/src/index.ts`）

**有序系统区段、动态上下文、工具 schema、提示词变量的注册表**。

| 概念 | 说明 |
|---|---|
| `PromptSection` | 系统提示词区段：唯一 `name`、`order`（约定：`-100` harness 身份、`0` 部署 persona、工具指导 100–199）、`text`（静态或每次装配求值的 provider，可含 `{{variable}}`）、`complete`（声明为完整系统提示词；多个有效 complete 区段则装配失败） |
| `PromptContext` | 动态模型上下文，物化为持久 user 角色快照（`ContextSnapshotSection`） |
| `PromptVariable` / `renderPrompt` | 装配后进行 `{{variable}}` 插值 |
| `PromptAssembly` / `AssembleContext` | 装配产物与上下文（`scope` + `signal`；dsh-agent 扩展其上挂 `agent`） |

事件：`system-prompt/assemble`（waterfall，专家监听器可改装配结果；已注册的 complete 区段在 waterfall 后恢复，监听器无法增删该作用域的系统提示词）、`system-prompt/change`（emit，任何 provider 变化）。

## 7. dsh-llm（`packages/llm/llm/src/index.ts`）

**LLM 服务**：适配器注册表 + waterfall 可拦截的流式调用 API。

### LlmRuntime（`ctx.llm`）与适配器

| 符号 | 说明 |
|---|---|
| `LlmAdapter`（抽象类） | provider 后端契约。唯一必须实现：`abstract stream(options: GenerateOptions): AsyncIterable<StreamChunk>`；可选 `providerInfo` / `providerRetryPolicy` / `listModels` / `resolveModel`。每个 provider HTTP 请求必须带 `attributionHeaders()` |
| `LlmRuntime.registerAdapter(providers, adapter)` | 注册路由；返回 `AdapterRegistrationHandle`（disposer + 同实例的原子路由替换） |
| `llm/stream` 事件（waterfall） | 包裹每次流式模型调用（重试、重放、路由）；`next()` 到达已解析适配器的流，或产出自己的 chunk 短路。loop 构建的请求带 `markAgentLoopRequest` 身份并深冻结（内容是日志的纯函数，监听器只读不改） |
| `PreparedLlmCall` | 配置与适配器注册一并解析的单次调用；`stream(options)` 经捕获的注册派发，复用/不匹配报 `INVALID_PREPARED_CALL` |

### 词汇表与错误

- `Message` / `freezeMessage` / `ContentBlock` / `ToolSchema` / `GenerateOptions` / `StreamChunk` / `LlmModelInfo`（`types.ts`、`message.ts`、`content.ts`）。
- `BlockAssembler`（`assembler.ts`）— chunk 组装。
- `LlmError extends HarnessError` — 携带 `LlmFailure`（`code` 如 `AUTH` / `RATE_LIMIT` / `NO_ADAPTER`、`status`、`providerRetryAfterMs`、`requestId`）。
- `assertUsableApiKey(raw, pkg, ref)` — 凭据诊断（key 永不进错误消息，只指名修复位置）。
- `deepFreeze` / `callConfigEquals` / `resolveRetryPolicy`（`ResolvedRetryPolicy`）。

| 包 | 说明 |
