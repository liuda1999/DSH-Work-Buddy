## 二、本次修复内容

### 1. 设置中心：大模型 API 配置（新功能，替代"界面构建中"占位页）
- DeepSeek 官方卡：API Key 保存/清除（`credentials.set/unset`）、模型目录编辑、maxTokens/默认上下文
- 默认模型卡：Provider/模型/推理强度（`settings.mutate` 写 `agent-default-model`）
- 自定义 Provider 卡：OpenAI 兼容/Anthropic 兼容接口添加与移除（`settings.mutate` 写 `llm-pi-ai.providers.<route>` + `credentials.set`）
- 实测：e2e-settings.mjs **19/19 PASS**（含添加→刷新持久→移除→服务端核实）

### 2. 网关 Origin 重写（修复 iframe 内 harness API 全 403）
`server.js` `proxyHarnessRequest` 与 WS upgrade：转发时把 Origin/Referer 重写为 `http://127.0.0.1:3080`。

### 3. 工作区上下文打通（spec 核心："会话在工作区文件夹上下文中运行"）
`index.html` `ensureHarnessSession()`：
- 任务已有真实快照 → 直接恢复
- 无有效快照 → `workspace.create(任务工作区路径)`（幂等）→ `session.create(workspaceId)` → 回写真实 sessionId
- 只读模式（已完成/逾期）绝不新建会话
实测：任务回写 `session-9e403980-...`；harness 侧栏出现 WorkBuddy 工作区；JSONL cwd 正确。

### 4. 日程 harness 模式修复
- `extractEventTime` 增加 `time0`（流式块行时间字段）
- 计数口径：仅 `user/message` 行计为一次对话，排除 chunk/usage/turn 边界/assistant 消息
- 实测：verify-schedule.mjs **4/4 PASS**（mode=harness、messageCount=2、cwd 正确）

### 5. 伪造快照清理
`tasks.json` 中 3 处 `test-sess-1` 伪造快照全部清除（任务状态字段不变）。

## 四、遗留问题（需用户知晓/后续处理）

1. **DeepSeek API Key 无效（环境问题）**：真实对话链路已打通（消息真实进入 harness 对话流），但模型调用返回 `API key is invalid (AUTH)`——`~/.dsh` 配置的 `DEEPSEEK_API_KEY` 无效或已过期。请通过新「设置中心 → 大模型 API 配置 → DeepSeek 官方」填入有效密钥后，会话即可真实对话；届时日程将自动进入 harness 模式展示每天对话次数。
2. **harness 图片附件**：上传的图片存储于 `~/.dsh/attachments/v1/objects/`（内容寻址），不在工作区目录；归档列表目前覆盖工作区目录文件（会话内 fs 工具写入的文件）。图片附件归档为后续增强项。
3. **硬编码演示内容**：3D 卡牌区、甘特图、KPI 增量文案、"刘馆长"身份为原演示页视觉组件，非数据功能，保留为视觉资产。
4. **今日待办分组口径**：`today` 为兜底组（未完成/未逾期/未开会话均入组，含未来到期），`dueToday` 高亮单独正确标注当日到期。
5. **llm-wiki 混合检索**：FastEmbed 因 HF 模型下载失败降级为词法模式，中文检索由网关 `localWikiMatch` 兜底（既有已知限制）。
