# 神秘工作区顽疾根治报告

- **日期**：2026-10-25
- **现象**：用户在对话窗口让智能体执行任务后，「全部工作区」经常出现新的空工作区（非每次必现）。历史版本多次"修过"（v0.1.995 幽灵目录、v0.1.996 神秘工作区）但反复复发。
- **本次残留**：`dsh-compaction-e2e`、`wb-mode-minimal-1788765791135`（+ 其下 3 个 `t_*` 嵌套），全部 taskCount 0。
- **结论**：**已根治（wb 层三层修复，harness 零改动），重启后存量已清零，复发场景实测被拦截。**

---

## 一、根因（这次挖到底了）

「全部工作区」面板 = 网关直连 harness `workspace.list` 后仅做一种过滤：`isTaskWorkspace(path)`，它只识别**项目数据根之内**的两种任务目录布局（`data/tasks/<id>` 旧布局、`data/workspaces/<名>/t_<id>` 新布局）。

而 harness 的**工作区注册表只增不减**：任何一次 `workspace.create` 都会永久留下注册。两条泄漏路径：

1. **历史测试根**：早期"极简模式"验证把任务根建在 `/tmp/wb-mode-minimal-<ts>/`，产生了真实任务（任务目录里还留着当日的 AGENTS.md，内写"此为当前任务专属文件夹"），任务与目录早已消失，注册永久残留。路径在项目外，`isTaskWorkspace` 判定 `false` → 以顶级工作区身份出现在面板。
2. **历次发版的 E2E 探针**：每个 release 的验证脚本直接 RPC `workspace.create('/tmp/xxx')`（本次的 `dsh-compaction-e2e` 即 v0.1.999 验证所留），目录一删注册即成幽灵。

**"对话后经常出现"的触发模式**：凡是让智能体做验证/诊断/测试类任务（历次发版自查皆如此），其脚本在 /tmp 注册工作区 → 面板多一个空工作区。v0.1.996 的修复只扩大了项目内布局的识别面，没有堵"项目外注册"这个口，也没有任何回收机制——所以复发。

## 二、修复（server.js，三层防御）

| 层 | 机制 | 作用 |
|---|---|---|
| 展示过滤 | `GET /api/workspaces`：非受管根（`data/workspaces`/`data/tasks` 之外）且无任务绑定的注册不返回 | 外部注册**永不进面板**（注册本身保留，活跃测试会话不受影响） |
| 启动自愈 | `sweepGhostWorkspaces()`：harness 就绪后扫描，项目外 + 目录已消失 + 无任务绑定 → `workspace.delete` 解除注册（失败自动重试 5×5s，防 RPC 表面滞后） | 幽灵注册**自动回收**，harness 侧栏同步干净 |
| 存量清理 | 本次已清：`dsh-compaction-e2e`（手动）+ 4 个 wb-mode-minimal（首启自愈，日志留痕） | 面板与注册表双清零 |

红线保持：清扫只解除注册，**永不触碰磁盘数据**（与既有"删除工作区不删文件"语义一致）。

## 三、验收（2026-10-25 实测）

1. 重启后面板仅剩 `生成(13 任务)`、`文件归档(4 任务)`，harness `/tmp` 注册数 0（总数 21→17）。
2. **复发场景模拟**：伪造 `/tmp/wb-ghost-probe` 注册 → 面板立即隐藏（目录存在也不显示）→ 删目录重启 → 注册被自愈清扫，harness 列表 0 残留。
3. 首版自愈曾在 RPC 未就绪时一枪哑火（已修：失败重试），journal 可见 4 条"幽灵工作区已自动清扫"日志。
